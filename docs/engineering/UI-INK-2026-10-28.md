分支 `arena/a5f6590e-rikkahub-agent-pure`，基线 `686bc40`（PR #442 之后）。
本轮动的是**审美方向**，不是交互流程：换掉默认主题、重排字阶与动效、重画消息气泡与输入条，并把同一套 token 落到 web-ui。

## 0. 一句话方向

**纸与墨：暖白的纸、炭黑的墨，全场只有一个强调色（青瓷），状态靠明度与位置说话，不靠阴影和五颜六色。**

| 关键词 | 做法 | 反面（改动前） |
|---|---|---|
| 纸不是白 | 浅色 `#FBFAF7`（L 0.985 微黄），深色 `#0D100F`（带一点绿调） | 纯白在夜里刺眼，纯黑在读文档时像关机 |
| 单强调色 | 青瓷（hue 187）。陶土（hue 45）只给「进行中/需注意」 | 七个预设主题各有一套强调色，默认落在樱粉 |
| 层级靠色阶 | `surfaceContainerLow → High` + 1dp 淡描边 | `tonalElevation` 阴影：浅色看不见、深色像脏污 |
| 大字号收字距 | display/headline 统一 -0.1 ~ -0.5sp | Material 默认字距在 28sp 以上是散的 |
| 正文给行高 | bodyLarge 1.5 → 1.56，bodyMedium → 1.57 | 长回答一屏 30 行挤成一块灰 |

## 1. App 端（Jetpack Compose）

### 1.1 新默认主题 `ink`

新文件：`app/src/main/java/me/rerere/rikkahub/ui/theme/presets/InkTheme.kt`

- 插入 `PresetThemes` 列表**第 0 位**，`PreferencesStore` 取 `PresetThemes[0]` 作为新装默认，因此新安装直接是墨色；老用户 `themeId` 已落盘，不受影响。
- `findPresetTheme(id)` 的兜底从 `SakuraThemePreset` 改为 `InkThemePreset`（未知 id / 被删的自定义主题不再落回樱粉）。
- 语义分工：`primary` 青瓷 = 可交互/生效中；`tertiary` 陶土 = 后台任务进行中；`error` = 失败。三者色相相距 > 140°，色弱用户也能靠明度区分。
- 表面阶梯比之前拉得更开（light：`#FFF` / `#F7F6F2` / `#F2F1EC` / `#ECEBE5` / `#E6E5DE`），因为卡片层级全部由这五档承担。

字符串：`theme_name_ink` = `Ink` / `墨`（其余语区回退英文）。

### 1.2 字阶（`Type.kt`）

不再 `val Typography = Typography()`（Material 默认），改为 `base.copy(...)`，只调三件事：

| 项 | 调整 | 理由 |
|---|---|---|
| display / headline | 行高与字距收紧（`-0.25 ~ -0.5sp`） | 大字号在中英混排下默认字距过松 |
| body* | 行高提到 25/22/18sp | 中文长回答的阅读密度 |
| label* | 字距 `0.1 / 0.3 / 0.5sp` | 元信息（token 数、模型名、时间）靠字距退后，而不是继续降对比度 |

字号阶梯本身**不动**：那是无障碍与系统字号缩放最稳的一档，改它会连带破布局。

### 1.3 形状与动效（`Theme.kt`）

- 新增 `RikkaShapes`：6 / 10 / 14 / 20 / 28dp，`MaterialExpressiveTheme(shapes = ...)` 全局生效。
- `MotionScheme.expressive()` → **`standard()`**：这是一个挂着跑几小时、要一直盯着的界面，弹性回弹在反复出现的列表项/消息上就是噪音。

### 1.4 视觉基元（`UiVisual.kt`）

| token | 旧 | 新 | 用途 |
|---|---|---|---|
| `Radius.chip` | 8dp | 8dp | 小标签、内嵌块 |
| `Radius.field` | — | 14dp | 输入框、下拉面板 |
| `Radius.card` | 16dp | 16dp | 卡片 / Hero/ 统计条 |
| `Radius.sheet` | 24dp | 28dp | 底部弹层，肉眼能看出「浮在内容之上」 |

`SectionHeader` 从 `titleSmall` + `onSurface` 改为 `labelLarge` + `onSurfaceVariant`：组标题和卡片标题原本同族同色，只剩颜色差，扫读时会互相抢。

### 1.5 消息气泡（`ChatMessage.kt`）

- 用户气泡：四角一律 16dp → **18/18/18/6dp**（收紧的角朝说话人），并加一圈 `primary @ 14%` 描边。之前一屏十几个胶囊排下来看不出谁在说话，收角就是不占地方的「尾巴」。
- 助手气泡（开启气泡时）镜像成 18/18/6/18，内边距 8dp → 14×10dp。
- 「展开/收起」按钮：`shadowElevation = 1dp` → 1dp 发丝描边 + 28dp 尺寸。阴影在深色主题上是脏污。

### 1.6 顶栏与建议胶囊（`ChatPage.kt` / `ChatList.kt`）

- 玻璃按钮 40dp → 36dp、间距 4→2dp：三连按钮不再像三个并列主操作。
- 会话标题 `bodyMedium` → `titleSmall`（同字号、weight 500）：一行标题就有标题的重量，不放大字号。
- 副标题（助手 / 模型 / token 数）对比 0.65 → 0.55，字距 0.4sp。
- 建议胶囊：`surfaceColorAtElevation(2dp)` → `surfaceContainerLow` + 发丝描边，文字用 `labelLarge`；之前浅色主题下几乎和背景同色，看不出能点。

## 2. web-ui（React + Tailwind v4）

### 2.1 token（`app/app.css`）

`:root` / `.dark` 全部换成与 `InkTheme.kt` 同一套 oklch 取值（青瓷 hue 187、暖纸 95、炭 165），并补齐：

- `--chart-1..5`：青瓷 / 陶土 / 苔绿 / 石板 / 米黄；
- 阴影：**只用于浮层**（popover/dialog/dropdown），且始终配 1px 描边；深浅两套分别是低透明度黑与 `oklch` 冷黑；
- `--radius: 0.75rem`（12px 基准，`radius-sm/md/lg/xl` 由它派生）；
- `--font-sans` 补上 `PingFang SC / Noto Sans SC`，中文不再靠字体回退碰运气；
- base 层：`color-scheme` 跟随主题、`::selection` 用主色 24%、`:focus-visible` 统一 2px 青瓷环、滚动条细化并在 hover 时加深、正文 `line-height: 1.6`、标题 -0.015em。

其余主题（claude / t3-chat / mono / bubblegum / custom）**未改动**，仍可在设置里切换。

## 3. 兼容与风险

- **老用户不受影响**：主题是显式 id 存在偏好里的，只有新装/陌生 id 才落到墨色。
- **动态取色**（`settings.dynamicColor`）优先级高于预设主题，行为不变。
- **形状与字体改动是全局的**：所有页面共用 `MaterialTheme.typography/shapes`，因此设置页、工作台、任务详情也会跟着变——这是有意的，避免「三个产品感」。
- App 端沙箱内没有 Android SDK，**未编译**；改动集中在主题常量与自包含的 `@Composable`，未触碰业务逻辑。

## 4. 第二轮：交互、布局、动效（同一天，允许大改）

上一节只动「皮」。这一节动「骨」：动效刻度、顶栏折叠、输入条的按钮分工、动作条的按需展开、空会话开场。
原则没变——**每一次动都要有一个可解释的因果**，不用装饰性动画。

### 4.1 动效刻度 `ui/theme/Motion.kt`（新）

只有三档时长，对应三个用途：

| token | 时长 | 用途 |
|---|---|---|
| `ENTER_MS` | 160ms | 内容出现（消息、动作条、建议胶囊） |
| `EMPHASIS_MS` | 240ms | 容器形变（输入条展开、气泡高度、顶栏收起） |
| `EXIT_MS` | 120ms | 内容消失——比出现更快，消失不需要被看清 |

缓动统一到一条类 Material 标准曲线（`CubicBezier(0.2, 0, 0, 1)`）。之前各处混用
`FastOutSlowIn` / `LinearOutSlowIn` / `spring`，同一屏里两条曲线叠加时，一个元素已经停住、
另一个还在漂，观感像掉帧。并预置 `contentEnter/contentExit`（淡入 + 1/8 高度位移）与
`popEnter/popExit`（淡入 + 92% 缩放）。

### 4.2 顶栏随滚动折叠（`ChatPage.kt`）

- 由 `chatListState` 的 `firstVisibleItemIndex / firstVisibleItemScrollOffset` 推出 `0f..1f` 的收起进度
  （96px 内完成），经 200ms 动画驱动三件事：顶栏底色浓度（0 → 92% surface）、
  底部发丝线透明度（0 → 55% outlineVariant）、元信息行（助手 / 模型 / token）的 alpha 与 4dp 上移。
- 结果：列表滚到中段时，正文从一条半透明栏下淡出，而不是直接压在标题上；回到顶部则完全透明，
  顶栏与正文重新连成一片。
- 三个属性共用同一个 fraction，避免「底已经实了但线还没出来」的错位。

### 4.3 输入条：按「范围 → 提交」重排（`ChatInput.kt`）

- 左侧（范围：这次要发什么）= **附件 + 模型/思考深度 + 全屏编辑**；
  右侧（提交：发出去）= **搜索 + 停止 + 发送**。全屏编辑从右侧挪到左侧，右侧不再有三颗等重的按钮。
- 发送圆盘：可用时 26dp → 32dp，图标 88% → 100%（200ms）；不可用时保持小盘。
  整个输入条只有它会在可用状态变化时「长大」，主操作一眼可辨。
- 点击热区 30/36dp → 40dp，视觉尺寸不变成肥大的按钮，但触摸更好点。
- 胶囊/卡片圆角 28→26、16→20，与 `Radius.field`、`Radius.card` 同宗。

### 4.4 消息动作条按需展开（`ChatMessage.kt`）

- 之前：除最后一条外，每条有内容的消息下面常驻一整排图标（复制、重新生成、分支、朗读、翻译…），
  一屏十几条消息就是十几排按钮，正文层级被吃掉。
- 现在：**只有最后一条常开**（刚生成的东西最可能要操作），历史消息默认收起，
  在消息下方给一个 16dp 的「⋮」，点开才出现动作条；再次点击或切换消息收起。
- 展开/收起走 `contentEnter/contentExit`，高度变化交给 `animateContentSize()`。

### 4.5 列表入场与空会话开场（`ChatList.kt`）

- 消息项加 `Modifier.animateItem()`：新消息从下方淡入并顶开已有内容；自动压缩合并消息组时也不会跳。
- 空会话不再是一片空白：列表第 0 项是 `ChatEmptyHero` —— 助手头像 56dp + 按时段的问候
  （`Greeting`）+ 助手名 + 一句提示 +（有则）最多 4 个建议胶囊（`FlowRow`，居中，发丝描边）。
  因为它是列表项而不是覆盖层，首条消息出现时会被自然顶上去，不需要额外的显隐状态机。

| 位置 | 改动 |

| `routes/conversations.tsx` | 空会话换成同样的开场（头像 + 按时段问候 + 提示 + 一层很淡的主色径向光）；消息项 `animate-in fade-in slide-in-from-bottom-1.5`；顶栏滚动后加深底色并浮出描边，回顶恢复 |
