## 二、问题清单（按严重性）

### P0

**#1 任务详情首屏被“目标原文”长文本占满，状态/进度/操作全部掉到首屏之外**
- 证据（device）：进入「工作台 → 我的任务」，页面 42 个可见节点里只有一个 `TextView` 撑满整屏 `[120,383,1320,3096]`，内容就是任务目标原文（数千字提示词）；标题栏只有“返回 + 标题 + 更多”，页面内看不到状态、进度、运行控制。
- 证据（source）：`pages/workbench/MissionDetailPage.kt:278-285` —— Hero 卡片直接 `Text(text = m.description)`，无 `maxLines`、无折叠；`description` 在 Moxw 里通常就是整段任务提示词（`CreateMissionSheet` 的描述字段与该值同源）。
- 影响：任务详情的“第一眼”信息为零，用户必须滑过数千字才能看到「开始/停止/验收」，长任务反馈形同不可见。
- 修复：默认折叠 3 行 + 「展开/收起」，仅在文本真的溢出时才出现折叠入口。

### P1

**#2 生成过程中，输入框一旦有字就再也停不下来**
- 证据（source）：`components/ai/ChatInput.kt:617` `val showStop = loading && empty`；`:388-403` 的 `when` 分派只在 `loading && state.isEmpty()` 时才把发送键画成「停止」。草稿非空时该槽位回到「发送」，`onCancelClick` 在整个输入区没有任何其他入口（全仓 `onCancelClick` 只出现在 `ChatInput`）。
- 影响：这是取消链路的硬伤——想停止正在跑的生成，必须先清空草稿。而发送在生成中本身是合法操作（消息队列 `MessageQueuePanel` 支持排队），两者被挤在同一个按键上。
- 修复：`loading` 时始终额外渲染一个独立的「停止」按钮，发送键保持发送语义，互不抢占。

**#3 抽屉底部 5 个入口全是纯图标，没有可见文字**
- 证据（device）：底部一排 5 个 60dp 圆形节点，节点树上只有 `contentDescription`（助手设置 / 菜单 / 收藏 / 统计数据 / 设置），没有任何 `TextView`。
- 证据（source）：`pages/chat/ChatDrawer.kt:1035-1075` `DrawerAction` = 42dp 圆片 + `Tooltip { label() }`，标签只在长按后出现；其中 `助手设置` 与 `设置` 两个齿轮类图标相邻，靠猜。
- 影响：抽屉是 Moxw 唯一的全局导航（对话列表 + 5 个目的地），5 个目的地里有 2 个长得像，图标语义还不唯一（`Sparkles` = 菜单）。
- 修复：图标下常驻一行 11sp 标签，保留圆形图标语言。

**#4 新建任务表单：主操作「创建」在滚动末尾，且与整张长表单抢空间**
- 证据（source）：`CreateMissionSheet.kt:176-181` 整个 sheet 是一个 `Column(verticalScroll)`，`mission_create_confirm` 按钮是最后一个子项（`:556-573`）。
- 影响：表单包含 标题/描述/验收标准×N/执行助手/工作区/工作流/启动方式/时间/冷却/上限，手机上必然长于一屏；键盘弹起时「创建」被推得更远，用户不知道要滚到底才能提交。
- 修复：内容区可滚动 + 底部固定操作条。

**#5 工作台统计条里「待验收」与另两个格子外观一致，但只有它在非空时可点**
- 证据（device）：`待验收` 格子节点 `clickable:false, enabled:false`（因为当时计数为 0），与左右两个纯展示格子无法区分。
- 证据（source）：`WorkbenchContent.kt:81-91` `clickable(enabled = reviewMissions.isNotEmpty()) { onNavigateDetail(reviewMissions.first().id) }`。
- 影响：同一个控件在不同数据下有时能点有时不能，且没有视觉提示；点了也只是跳到第一条待验收任务。
- 修复：与列表分组行为对齐——非空时给可点提示（强调色/箭头），为 0 时保持纯展示。

### P2

**#6 任务卡片只有文字进度（`0/6 验收`），没有进度视觉** — `WorkbenchComponents.kt:176-186`；长任务最需要的“大概到哪了”只能读数字。修复：加 4dp 细进度条。

**#7 任务卡片上「运行中」圆点 + 状态药丸「进行中」两个近义状态并列** — device 观察到同一行同时出现 `运行中`（执行态）与 `进行中`（任务态），中文里几乎同义。修复：执行态改用“运行中 · 12 分钟”这类带时长的形式，与任务状态区分。

**#8 消息操作图标触控尺寸不统一（复核后不改）** — 一处消息测得 `[480,2060,630,2195]` = 50×45dp，另一处测得 `[82,793,230,970]` = 49×59dp；source 为 `padding(8.dp).size(16.dp)`，实际可点区域由 FlowRow 行高决定。实测已基本达到 48dp，**本轮不改**（改了只是给已达标的地方再加内边距），只记为后续统一项。

**#9 抽屉里「聊天 / Agent / 新建」三分段把动作（新建）混进导航项** — device 观察到三个并列 `Text` 段；`新建` 是动词，点击后是创建流程而不是切换视图。（本轮先记录，是否改动待评估，避免动到既有习惯。）

**#10 系统返回在会话页直接退出 App（未改，需产品决策）** — device 复现：在会话页按一次返回，`com.moxw.agent` 直接退到后台（Chrome 露出），而不是回到对话列表；dispatch 也不是打开抽屉。这和 Moxw 的导航模型有关：Chat 是返回栈根，对话列表只是抽屉（`RouteActivity.kt:314-320` 只有 `Screen.Chat`，没有 ChatList 目的地）。改成“返回即打开抽屉/回到列表”会改变根导航语义，**本轮不动**，只作为建议（见第六节）。

## 三、明确不改的东西

- 模型调用、任务引擎、计费、权限、数据层：本轮零改动。

## 六、未做但建议（需产品/发版决策）

1. 会话页返回：可以让系统返回先打开抽屉（`BackHandler { drawerState.open() }`）或引入“列表即根”的两层返回栈；这会改变现有单根导航，需先确认习惯。
2. 工作台统计三格：`待验收` 建议始终可点，跳到「待验收」分组（现在只在非空时跳第一条），或为 0 时置灰显示。
3. 抽屉里「聊天 / Agent / 新建」三分段：`新建` 是动作不是视图，长期看应拆成独立按钮。
4. 任务详情的首屏还可以再压缩：`workflow label`、`created/updated` 与 `bound conversation` 三行可以合并成一行元信息。
